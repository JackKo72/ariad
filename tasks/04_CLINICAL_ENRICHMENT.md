# Task 04: Clinical Enrichment

## 배경

ASR 전사문과 기존 structure_llm 사이에 "임상 의미 정리(clinical enrichment)" 단계를
설계하고 구현한다. tasks/03_SPEAKER_MERGE_AND_LATENCY.md의 ASR 지연 진단과는 별도
단계로 다루고, 이 단계 자체의 추가 처리 시간도 측정한다.

목표는 구어체 진료 대화를 의료진이 검토하기 쉬운 구조로 바꾸는 것이다. 원본 전사문은
보존하고, 의학적 해석은 원문에 연결된 후보로 제시한다.

## 1. 조사 + 삽입 위치

구현 전 현재 ASR 출력 형식, 화자 정보, structure_llm 입력, `sample_consultation.
transcript.json`의 정답 항목을 확인하고, 기존 API와 문서 생성 흐름을 깨지 않는 삽입
위치를 제안한다.

## 2. 추출 항목

다음 정보를 구분해 추출한다.

- 약물: 원문 표기, 표준화 후보, 성분/상품명, 용량, 투여 경로, 빈도, 복용 시점,
  시작·중단·변경 여부
- 증상과 기능: 환자 진술, 보호자 진술, 의사의 질문을 구분
- 진찰: 검사 지시, 실제 관찰 결과, 점수 산출 가능 여부를 구분
- 진단: 확진, 의사가 명시한 감별진단, 모델이 제안하는 추가 확인 질문을 서로 다른
  필드로 구분
- 계획: 의료진이 실제로 지시한 행동과 단순 논의를 구분

## 3. 항목 필드

각 항목에는 원문 구절, 화자, 시각 정보(있으면), 긍정/부정/질문/불확실 상태, 정규화
후보, 판단 근거, "의료진 확인 필요" 여부를 포함한다. 약물명이나 용량이 모호하면 하나로
임의 확정하지 않는다. 기존 복약목록과 전사가 다를 때도 전사를 조용히 덮어쓰지 않는다.

## 4. 금지 사례

- "다리 들어보세요"만으로 mRS·NIHSS·MRC 점수 생성 금지
- "다리를 끄나요?"라는 질문만으로 보행장애 확정 금지
- "잠을 잘 못 자요"만으로 r/o RBD 생성 금지
- "약을 끊지 마세요"의 부정 누락 또는 중단 지시로 반전 금지

RBD와 관련된 구체적 야간 행동이 언급되더라도, 의사가 명시하지 않았다면 진단 대신
"추가 확인 후보"로 표시한다.

## 5. 평가

기존 59.5초 합성 샘플(sample_consultation)의 sidecar 정답을 먼저 사용하고, 별도의 약
3분짜리 2인 이상 대화 샘플에서도 시험한다. 전사 정확도(CER), 약물명·용량·부정 표현의
정확도, 질문을 소견으로 잘못 바꾼 횟수, 근거 없는 점수·진단 생성 횟수, 화자 배정 오류,
추가 처리 시간과 전체 처리 시간을 따로 보고한다. 3분 샘플을 실제로 실행할 수 없으면
성능을 추정해 적지 않고 실행 방법과 미측정 항목을 명시한다.

## 6. 결과 보고

결과를 원문 / 정리 결과 / 기대 결과 / 오류 유형 표로 보여주고, 정확도가 확인된 변환만
기본 경로에 적용한다.

## 7. 목표 지연

3~10분 정도의 대화가 오고갔을 때 1분 미만으로 정리본이 나오는 것을 목표로 한다.
